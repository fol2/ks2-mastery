# Next Punctuation Subject-Quality Contract

The next valuable improvement should remain subject-content focused, not a UI reshape. The session frame is already stable enough; the higher-value path is to keep removing subtle ways the generated bank can teach through weak examples.

## Recommended next probes

1. Direct speech examples should never teach a reporting-comma rule while also making quote/sentence grammar ambiguous.
2. Semicolon examples should block `; because ...` and fragment-style semicolon misuse across model and distractor surfaces.
3. Dash-clause examples should explicitly decide whether the learner-facing production surface is ASCII spaced hyphen, en dash, or em dash, then keep marking acceptance separate from display quality.
4. Bullet-point items should distinguish consistent bullet punctuation from ordinary line breaks, so children learn list style rather than just copying hyphen-prefixed lines.
5. Apostrophe possession should separately gate singular, regular plural, and irregular plural examples so edge cases remain intentional rather than accidental.

## Extra-credit direction

Add a small extension bank that asks children to explain the punctuation choice after they correct it. Do not score these as normal mastery until the explanation rubric is reliable. Use them as “challenge / extra credit” practice that strengthens transfer without inflating Stars.

Suggested first extension shape:

```text
Correct the sentence, then choose the reason.
```

Reason choices should be rule-specific:

```text
The comma separates a fronted adverbial from the main clause.
The comma separates items in a list.
The comma separates speech from the reporting clause.
```

Acceptance boundary: no new reward inflation, no per-question currency, and no “Mega” acceleration from explanation-only attempts.
