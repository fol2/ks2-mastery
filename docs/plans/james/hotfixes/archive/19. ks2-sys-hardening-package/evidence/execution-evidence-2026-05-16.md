## Implementation Summary

- `Retry-After` is parsed from HTTP headers and JSON payloads, propagated into persistence error details, and used to cap bootstrap 429 backoff.
- HTTP 429 is classified as retryable for repository calls and bootstrap recovery.
- `HttpError` responses with `retryAfterSeconds` now emit a `retry-after` header. Compatibility-sensitive auth, demo, and TTS `BadRequestError` rate-limit paths keep their existing HTTP status while carrying the retry header.
- Demo session start now collapses concurrent clicks into one `/api/demo/session` request and resets only after a failed start.
- `/api/version` returns a no-store build manifest, using `env.BUILD_HASH` first and the build-generated Worker module as fallback.
- The client checks the build version on app start, focus, visibility changes, and post-render safe points. It soft-reloads immediately when safe and shows a child-friendly banner while a learner is in subject work.
- Build tooling now writes `worker/src/generated-build-version.js` so production deploys can expose the current clean-tree build hash without relying solely on Cloudflare environment variables.
